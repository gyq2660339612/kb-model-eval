## 3. RAG 知识库场景的指标定义(本项目代码实现口径)

记号:对查询 q,`REL(q)` 为其全部相关文档集合,`rel(d) ∈ {0,1,2,...}` 为文档 d 的分级相关度(qrels 标注),`rank(d)` 为检索结果中的名次(1 起)。所有指标先对单查询计分,再对查询集取**算术平均**。

| 指标 | 定义 | 说明 |
|---|---|---|
| **Recall@k** | `\|Top-k ∩ REL(q)\| / \|REL(q)\|` | 召回覆盖率,**召回环节最核心指标** |
| **Hit Rate@k** | 1 若 Top-k 含 ≥1 个相关文档,否则 0 | 等价 Success@k;单相关文档时与 Recall@k 相同 |
| **Precision@k** | `\|Top-k ∩ REL(q)\| / k` | 前 k 条的精确率 |
| **MRR@k** | `1 / rank(首个相关文档)`;前 k 无相关记 0 | 强调第一个正确结果的位置,适合单答案问答 |
| **MAP@k** | `AP = (1/\|REL\|) Σ_{i:第i位相关} P@i`,取平均 | 兼顾相关文档集合整体排名质量 |
| **nDCG@k** | `DCG@k / IDCG@k`;`DCG@k = Σ_{i=1..k} (2^rel_i − 1)/log2(i+1)` | 支持分级相关度,**检索主指标**(trec_eval 增益形式) |

注意:

- nDCG 有两种增益形式:`rel/log2(i+1)`(原始)与 `(2^rel−1)/log2(i+1)`(trec_eval)。**本项目与 pytrec_eval/ranx 一致,采用后者**;与其他工具对分前务必核对。
- 比较不同模型/系统时必须固定 k、语料规模与 qrels,否则分数不可比。
- 分级标注建议:2 = 直接回答/核心文档,1 = 部分相关,0 = 不相关(不写入 qrels)。

## 4. 本项目评测维度(四大类)

1. **召回质量**(embedding):Recall@k、Hit Rate@k、nDCG@k、MRR@k、MAP@k,k ∈ {1,3,5,10,20,50,100}(按语料规模截断)。
2. **精排质量**(reranker):对召回 top-N(建议 N=100 或预算允许的最大值)重排后,对比重排**前后**的 nDCG@5/10、MRR@10、Recall@5/10 变化。
3. **性能**:向量化吞吐(docs/s、tokens/s)、query 端到端延迟(P50/P95/P99)、rerank 单 query 延迟、GPU 显存峰值。
4. **成本**:向量维度(MRL 档位)→ 存储;量化档位 → 显存与精度折损(需实测)。

## 5. 测试集(测试用例)构建规范

采用 **BEIR 格式**,三个文件:

```
data/<dataset>/
├── corpus.jsonl    # {"_id": "d1", "title": "标题", "text": "正文"}   每行一篇
├── queries.jsonl   # {"_id": "q1", "text": "查询"}                    每行一条
└── qrels.tsv       # query-id \t corpus-id \t score                   含表头行
```

构建要求:

- **语料(corpus)**:尽量使用真实知识库 chunk(与生产分块策略一致!);规模 ≥ 1000 条才有区分度,示例集仅作流程演示。
- **查询(queries)**:来源优先级:真实用户 query 日志 > 业务专家编写 > LLM 生成+人工过滤。覆盖:事实问答、概念解释、故障排查、参数查询、跨文档推理等类型;中英文按生产流量比例配比。
- **标注(qrels)**:双人独立标注 + 仲裁;分级 0/1/2;每个 query 至少 1 个 2 分文档;标注前先对候选池做"多模型召回并集 + BM25 并集"(pooling),避免漏标导致假负例。
- **规模建议**:query ≥ 100 条(50 条仅作 smoke test);正例文档 ≥ 150 篇。
- 项目自带 `data/sample/` 为半导体领域示例(22 篇文档、8 条查询),可直接跑通全流程。

## 6. 验收标准(建议门槛)

在自建领域测试集上,**准入/验收双门槛**(数值可按业务上调):

| 维度 | 准入门槛(可上线灰度) | 验收目标(正式切换) |
|---|---|---|
| Recall@10 | ≥ 0.80 | ≥ 0.90 |
| Hit Rate@5 | ≥ 0.85 | ≥ 0.92 |
| nDCG@10(召回) | ≥ 0.60 | ≥ 0.70 |
| nDCG@10(重排后) | 较召回 +5% 以上 | 较召回 +10% 以上 |
| MRR@10(重排后) | ≥ 0.70 | ≥ 0.80 |
| query 延迟 P95(召回) | ≤ 100 ms | ≤ 50 ms |
| rerank 延迟 P95(top-20) | ≤ 500 ms | ≤ 300 ms |
| 向量化吞吐 | ≥ 50 docs/s | ≥ 200 docs/s |

默认值存于 `configs/eval_config.json`,评测报告会自动对照门槛给出 PASS/FAIL。

## 7. 官方基准复现工具(可选)

| 工具 | 用途 | 用法要点 |
|---|---|---|
| `mteb` | MTEB/C-MTEB 全量复现 | `mteb.evaluate(model, tasks)`;CLI `mteb run -m <model> -t <task>` |
| `C_MTEB` | 中文榜单提交格式 | `pip install C_MTEB`,含 eval_cross_encoder |
| `beir` | BEIR 零样本检索 | `EvaluateRetrieval.evaluate(qrels, results, k_values)` 一次出 NDCG/MAP/Recall/Precision |
| `pytrec_eval_terrier` | trec_eval 指标 | 增益形式核对见 §3 |
| `ranx` | 指标 + 显著性检验 + 融合 | `compare()` 内置 t 检验/Fisher/Tukey;25+ 融合算法适合"向量+BM25"对比 |
