# 07 · 测试集构建与标注指南

> 本文是总框架([docs/00](00-评估体系总框架.md) §6、§9、§10.4)的落地版:数据格式以本项目代码为准,并给出半导体领域测试集的构建流程。
> **内部半导体测试集是最终验收主依据,公开榜单不能替代。**

## 1. 数据规模建议

| 阶段 | Query 数量 | 每 Query 标注量 | 用途 |
|---|---:|---|---|
| Smoke 冒烟 | 30–50 | ≥1 正例 + 若干难负例 | 验证脚本、接口、索引能跑通(本项目 `data/sample/` 即此级) |
| Pilot 试点 | 200–300 | 1–5 个相关文档,含相关等级 | 比较候选模型,暴露数据与标注问题 |
| 正式验收 | 800–2,000 起 | 相关文档池尽可能完整,0/1/2/3 分级 | 决策、发布门槛与回归测试 |
| 持续回归 | 每次新增 50–100 | 覆盖近期故障、新术语、误召回案例 | 跟踪模型/索引/文档变化 |

## 2. Query 类别分层(13 类)

正式测试集按以下标签分层,**每类单独出分**(代码按 `labels.category` 自动分层),防止总分掩盖关键缺陷:

| # | 类别 | 说明 | 示例 |
|---|---|---|---|
| 1 | direct_fact | 直接事实查询(规格、定义、材料) | "EUV光刻机的工作原理是什么" |
| 2 | synonym_paraphrase | 同义改写/口语问法 | "芯片表面磨平用的是什么工艺"(=CMP) |
| 3 | abbreviation | 缩写/别名/中英术语 | "刻蚀机台ICP和CCP的区别" |
| 4 | exact_match | 精确标识符:报警码、型号、配方号、料号 | "报警代码ALM-1042表示什么故障" |
| 5 | numeric_constraint | 数值/区间/单位/条件约束 | "PECVD工艺的沉积温度范围是多少" |
| 6 | complex_condition | 型号+步骤+材料联合约束 | "EQP-17 在 HBr 配方下的主刻蚀时间" |
| 7 | cross_lingual | 中文问英文档、英文问中文档 | "what is the overlay spec" 对中文 SOP |
| 8 | long_doc | 答案在长手册后部/长章节 | 跨页工艺规范 |
| 9 | table_structured | 需结合表头/行名解释 | 参数表、矩阵表 |
| 10 | hard_negative | 相邻型号、近似报警码、旧 recipe | ALM-1042 刻蚀 vs 退火(本项目 d23/d24) |
| 11 | version_temporal | 当前有效 vs 过期文档 | v2.1 与 v3.0 SOP 并存 |
| 12 | unanswerable | 语料中无可靠依据 | 本项目 q11;检查是否错误召回"看着像"的段落 |
| 13 | permission | 无权文档不得返回 | 系统层安全验收,非模型指标 |

半导体重点场景:制程工艺(步骤/窗口/参数上下限)、设备(系列/腔体/部件/保养/故障)、良率分析(缺陷分类/根因/相似案例)、规格与材料(化学品/耗材/兼容性)、故障代码(exact match + 同码不同设备 hard negative)、技术报告(跨页表格/结论与原始数据区分)。

## 3. 标注标准

- **分级相关性**(本项目代码支持任意等级,nDCG 增益 2^rel−1):
  - `3` = 直接回答问题、关键约束全部满足
  - `2` = 高度相关、可支持回答
  - `1` = 部分相关/背景信息
  - `0` = 不相关或条件冲突(**难负例要显式标 0 并写入 qrels**,如 d24/d26)
- 高风险案例(参数、版本、报警码)至少**两位领域人员复核**;随机抽检 ≥10% 标签。
- 严格约束类规则:关键约束(数值、型号、版本)错误的候选,即使语义相似也标 0。
- **相关文档池(pooling)**:不能只从当前模型 Top-K 里找正例——合并 BM25、多个 Embedding 模型的召回并集 + 人工检索 + 专家已知答案,避免漏标造成假负例。
- **防泄漏**:train/dev/test 按文档来源/家族/时间切分;同一文档的相邻段落不得同时出现在开发集与测试集;测试集不得用于微调;保留一份受控隐藏验收集。

## 4. 文件格式(本项目代码支持两种,可混用)

### 4.1 本项目默认(BEIR 风格)

```
data/<dataset>/
├── corpus.jsonl    {"_id": "d1", "title": "...", "text": "...", "metadata": {...}}
├── queries.jsonl   {"_id": "q1", "text": "...", "labels": {...}, "relevant_doc_ids": [...]}
└── qrels.tsv       query-id <TAB> corpus-id <TAB> score(表头可选,0-3 分级)
```

### 4.2 总框架 JSONL 风格(代码同样支持)

```
corpus.jsonl      {"id": "doc_0001", "text": "...", "metadata": {"source": "...", "language": "zh", "version": "v3", "chunk_index": 12}}
queries.jsonl     {"id": "q_0001", "text": "...", "relevant_doc_ids": ["doc_0001"], "labels": {"category": "alarm_code", "language": "zh", "difficulty": "exact_match"}}
qrels.jsonl       {"query_id": "q_0001", "doc_id": "doc_0001", "relevance": 3}
```

加载优先级:`qrels.tsv` > `qrels.jsonl` > `queries.jsonl` 的 `relevant_doc_ids`(按二元相关=1)。`id`/`_id` 两种键都识别。

### 4.3 冻结的重排候选集(candidates.jsonl)

总框架 §7.5 要求 reranker 评测**候选集固定**:

```json
{"query_id": "q1", "candidates": [{"doc_id": "d1", "initial_rank": 1}, {"doc_id": "d7", "initial_rank": 2}]}
```

生成方式(召回后冻结,供所有 reranker 复用):

```bash
python -m src.run_evaluation --backend openai ... --save-candidates --output-dir results/base-r1
# 之后每个 reranker 用同一候选集复测:
python -m src.run_evaluation --backend mock --rerank-backend openai \
    --rerank-model Qwen/Qwen3-Reranker-4B --candidates results/base-r1/candidates.jsonl
```

### 4.4 每条数据应保留的元数据

`dataset_version`、`source_document_id`、`chunk_id`、语言、类别、难度、相关等级、来源文档 revision、是否含精确标识符、是否含数值约束、标注人/审核人、标注时间。**含商业机密的真实语料必须脱敏后才能进入评测仓库;Git 仓库只放公开/合成/去标识化数据。**
