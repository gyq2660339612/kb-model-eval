# 08 · 实验流程、评分规则与报告模板

> 本文把总框架([docs/00](00-评估体系总框架.md) §1.2、§8、§11–§14、附录)落到本项目代码:怎么跑实验、怎么评分、结果怎么存档。

## 1. 评测的三个层次(不要混为一谈)

| 层次 | 被测对象 | 本项目入口 | 主要指标 |
|---|---|---|---|
| L1 模型能力 | Embedding | `run_evaluation.py --backend ...`(无 rerank) | Recall@K、Hit@K、nDCG@K、MRR@K |
| L2 重排能力 | Reranker | 固定候选集 + `--rerank-backend ... --candidates ...` | nDCG@K、MRR@K、MAP、Pairwise Accuracy、ΔnDCG |
| L3 系统能力 | 完整链路 | L1+L2 组合 + 压测 + 权限测试 | 端到端质量、P50/P95、QPS、显存、成本、失败率 |

**铁律**:评 Reranker 必须固定候选集(同一召回基线产出、冻结存档);否则分数混合了召回差异与重排差异。

## 2. 最低实验组合清单(总框架 §3.3)

1. Qwen3-Embedding-0.6B + Qwen3-Reranker-0.6B
2. Qwen3-Embedding-4B + Qwen3-Reranker-4B
3. Qwen3-Embedding-8B + Qwen3-Reranker-8B
4. BGE-M3 dense-only
5. BGE-M3 dense + sparse 融合(如系统支持)
6. 一个中文 BGE embedding + bge-reranker-v2-m3
7. **BM25-only 基线**(`--backend bm25`,本项目已实现纯 Python Okapi BM25)
8. 不使用 reranker 的 dense-only 基线

另加**交叉组合**:同一组冻结候选分别送入 Qwen3-Reranker 0.6B/4B/8B 与 BGE reranker,不要只测"Qwen 对 Qwen、BGE 对 BGE"。

## 3. 综合评分与硬门槛

### 3.1 推荐权重(总框架 §8.1)

| 一级维度 | 权重 | 说明 |
|---|---:|---|
| 检索质量 | 35% | 内部 Recall@20、nDCG@10、MRR@10;公开 C-MTEB/MTEB Retrieval 补充 |
| 重排收益 | 25% | 内部 nDCG@10、MRR@10、Precision@5、ΔnDCG@10 |
| 半导体专项 | 15% | exact match、数值约束、版本区分、难负例、跨语言分层分数 |
| 推理性能 | 10% | P95 延迟、吞吐、启动时间、错误率 |
| 资源与成本 | 10% | 峰值显存、GPU 小时、索引空间、每百万查询成本 |
| 稳健与可运维 | 5% | 长度敏感性、重复性、离线可部署、版本可追踪 |

- 每项先映射 0–100 子分再加权,**不得把原始 nDCG、毫秒、GB 直接相加**。
- 权重在测试开始后不得为让某模型获胜而临时调整。
- 本项目 `configs/eval_config.json` 的 `composite_score` 自动计算可量化的质量部分;性能/成本/稳健项压测后人工补录。

### 3.2 硬门槛(优先于加权总分,试点建议起点)

- 内部 `Recall@20` ≥ 0.90(标注完整的可回答子集)
- 内部 `nDCG@10` ≥ 0.75(分级相关性,阈值需经 pilot 校准)
- 报警码/型号/版本等严格约束类:`Top-1` 正确率 ≥ 0.95 → 代码对应 `category_gates`(如 `exact_match: hit_rate@1 ≥ 0.95`);不达标不允许仅凭总分上线
- 重排后 nDCG@10 不低于重排前,且推荐统计上稳定的正向增益
- 目标硬件约定并发下,P95/峰值显存/错误率满足预算
- 权限隔离 100% 通过(系统层)

> 上述数值是**项目建议起点**,不是行业标准;可达值高度依赖语料、Query 难度、标注完整性与 chunk 方式。

### 3.3 统计可信度(总框架 §8.3)

- 所有模型在**相同 Query 集**上成对比较;同时报告绝对变化(+0.035)与相对变化(+4.8%)。
- 差异较小时不得凭 1 次运行下结论:性能测试 ≥3 轮;指标脚本确定性可复跑。
- 逐 query 配对 bootstrap:

```bash
python scripts/compare_runs.py results/runA/per_query_results.jsonl \
    results/runB/per_query_results.jsonl --metric ndcg@10
# 输出 Δ 均值、95% CI、逐 query 胜负统计;CI 含 0 → 差异不显著
```

## 4. 公开 benchmark 复现准则(总框架 §11)

每轮复现必须存档:评测框架精确版本/Git commit;数据集名称/版本/split/revision;模型 repo ID、revision/commit、权重精度与 **SHA256**;query 指令、max length、输出维度、归一化;batch、GPU 型号、CUDA/驱动、PyTorch/Transformers 版本;运行命令、起止时间、原始 per-task 分数;与公开榜单不同的任何设置及原因。

- **MTEB**:`pip install "mteb==<固定版本>"`,以当前官方文档(docs.mteb.org)为准;先跑小任务冒烟再整批;逐任务分数与榜单同名任务逐项核对;未完整运行的子集不得宣称复现整个榜单。
- **BEIR**:按官方协议,展示逐数据集 nDCG@10 而非只留均值。
- **C-MTEB**:锁定代码与数据版本;报整体分需注明任务数量与完整度。
- **MLDR**:长文档检索,对 max length/chunk/指令敏感,必须对齐配置。
- **MMTEB**:第一轮按业务语言选子集,报告中标注"业务相关子集"。

## 5. 结果目录与报告模板

`--output-dir results/<run_id>/` 自动生成:

```
results/<run_id>/
├── run_config.json           # 模型、参数、数据文件 SHA256、指令、k 值(代码自动写)
├── environment.txt           # Python/平台/numpy 版本(GPU 环境请补 nvidia-smi 与 pip freeze)
├── report.md                 # 人类可读报告(指标/分层/重排对比/门槛/综合评分)
├── report.json               # 机器可读完整结果
├── per_query_results.jsonl   # 逐 query 指标与 top 结果(失败分析、bootstrap 对比输入)
├── benchmark_summary.csv     # retrieval / rerank_before / rerank_after 指标汇总
└── candidates.jsonl          # --save-candidates 时生成,冻结重排候选集
```

压测与正式实验还需补充:`latency_profile.csv`(长度×batch×并发矩阵)、`errors.jsonl`、`model_hashes.sha256`、`pip freeze > requirements-lock.txt`。

报告必须包含:① 比较目的与测试版本;② 硬件/精度/框架/关键参数;③ 公开 benchmark 任务清单与完整度;④ 内部测试集版本/样本数/标注规则;⑤ 初召回指标、重排前后指标、差值与分层结果;⑥ 延迟/吞吐/显存/失败率/单位成本;⑦ 典型成功与失败样例人工归因;⑧ "公开分数与内部得分不可直接等价"的说明;⑨ 推荐结论、风险、部署参数与回滚方案。

## 6. 实施顺序(Phase 0–5)

- **Phase 0 冻结协议**:定候选模型/版本/许可;30–50 条 smoke case;冻结指标定义、硬件、batch、max length、指令、距离函数;定标注规则。
- **Phase 1 公开基准**:复现主要检索基准,逐任务出分;官方参考值/当前榜单值/本地复现值分列。
- **Phase 2 内部初召回**:同 corpus、同 chunk、同 query 集对比所有 Embedding;先用精确检索隔离模型差异,再评 ANN 近似误差;对比维度(MRL)/指令/chunk 长度。
- **Phase 3 固定候选重排**:基线召回 top-100 冻结;对比各 reranker;报告前后指标、分层变化与延迟;换候选来源验证泛化。
- **Phase 4 端到端**:dense-only / BM25-only / hybrid / rerank 链路;top-k、融合策略、候选数、chunk、维度组合;完整 RAG 的答案正确性/引用支持/拒答单独测,不计入 Embedding 分数。
- **Phase 5 部署压测与准入**:长度×batch×并发矩阵;≥30 分钟持续压测与重启恢复;硬门槛+加权分数决定上线;保留回滚配置与上版结果。

## 7. 最小上线决策规则(全部满足才进入上线名单)

1. 核心内部检索指标过线,且报警码、数值约束、版本区分、跨语言等关键类别无严重退化;
2. Reranker 在相同候选集上有稳定收益,或清楚证明无需 reranker 即可达标;
3. 目标硬件下 P95、QPS、显存、错误率符合预算;
4. 离线部署成功,模型与依赖版本可追溯,具备回滚方案;
5. 评测报告包含公开基准与内部结果、全部异常与已知限制,**不把未复现的官方分数写成自测成绩**。
